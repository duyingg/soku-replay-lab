# 播放页面板布局改版方案

日期：2026-10-24  
项目：Soku Replay Lab · 非想天则复盘工作台  
状态：调研与设计方案，尚未实施本轮布局改版。

## 1. 改版结论

播放页采用 AE / Premiere Pro 的停靠面板思路：**中央显示游戏，侧边分组显示辅助信息，下方固定时间轴和唯一一组播放控制。** 面板共享分隔线，调整一个区域时相邻区域跟随调整，不再在一张长画布上分别拖动矩形。

本次目标是重新组织已有功能。已删除的输入录制、重复播放按钮和重复速度栏不恢复。逃压推演继续保留独立页面。

以下尺寸、分组和交互是针对本项目的设计建议，不是 Adobe 官方规格，也不表示已经实现。

## 3. 当前页面为什么不好用

以下依据当前源码检查，位置见 `ReplayWorkspace.cs`、`MainWindow.cs` 的 `ReplayPage`、`BuildTransportBar` 和 `PopulateReplayTools`。

| 当前结构 | 问题及影响 | 改版处理 |
| --- | --- | --- |
| `ReplayWorkspace` 使用 Canvas 和每个面板独立的 X / Y / Width / Height | 面板可以互相覆盖，移动后相邻面板不补位 | 换成分割区域与标签组 |
| 工作区初始高度为 1030，部分辅助面板默认位置达到侧栏 Y=806 | 页面内容容易延伸到可视区下方；看工具时可能失去游戏画面 | 工作区高度服从实际窗口，长列表在面板内部滚动 |
| 小宽度时辅助面板排到画面下方，起点增加到 662 | 窄窗口进一步变成长页面 | 小窗口改为标签合并，避免整页纵向堆放 |
| “对局画面与当前状态”里同时有状态文字、双方抽牌列和步进按钮 | 状态区高度、两侧卡牌列共同挤压游戏画面 | 状态和卡牌转入辅助面板，中央主要留给游戏 |
| 卡牌列各占 78，画面可用宽度还要扣除额外间距 | 小窗口中画面缩小较明显 | 卡牌列表不常驻画面两侧 |
| 多个面板正文包裹 ScrollViewer，内部列表又有自己的滚动区域 | 容易形成嵌套滚动，滚轮目标不清晰 | 每个长列表只保留一个滚动容器 |
| 时间轴和播放按钮在应用底部，当前帧说明又在画面上方 | 画面、时间与状态之间距离较大 | 时间轴固定在播放工作区下沿，保持邻近关系 |

快速定位此前只显示前 10 个事件的问题已修复。布局改版必须保留全部事件，以及已经验证的虚拟列表能力，不能再以减少条目来提高速度。

## 4. 推荐默认布局

下面表示播放页的内容区域；应用已有的页面导航保持原有职责。示意比例不作为硬编码像素值。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 当前 REP 名称 / 原回放或技能分支 / 游戏连接状态 / 恢复默认布局             │
├─────────────────┬───────────────────────────────────┬────────────────────┤
│ 快速定位        │ 对局画面                          │ 当前状态           │
│ 固定快照        │                                   │ 压制缝提示         │
│ 时间标记        │                                   │ （标签切换）       │
│ （标签切换）    │              游戏实机画面         │                    │
│                 │              保持 4:3             │ 1P / 2P 状态       │
│ 完整事件列表    │                                   │ 卡牌与抽牌顺序     │
│ 时间 / 类型     │                                   │                    │
│ 简要说明        │                                   │                    │
│                 │                                   │                    │
├─────────────────┴───────────────────────────────────┴────────────────────┤
│ 回放进度 / 时间刻度 / 已确认的当前位置                                   │
│ 播放·暂停  步进  当前时间/总时长  倍速  接管  [分支时：返回原回放]        │
├──────────────────────────────────────────────────────────────────────────┤
│ 状态：已暂停 / 正在定位目标帧 / 正在恢复原回放 / 错误说明                 │
└──────────────────────────────────────────────────────────────────────────┘
```

### 中央：对局画面

- 获得剩余可用空间，始终保持 4:3。宽高按可用区域同时约束，四周留空，不拉伸、不裁切游戏。
- 标题保持一行。详细生命、灵力、动作名称和卡牌不再挤占画面上方或两侧。
- 未连接时显示明确的离线占位；连接失败显示恢复入口。占位区域尺寸不因文案长度跳动。
- 技能分支播放时清楚标注“技能分支”，并保留“返回原回放”。不可只靠颜色表达。

### 左侧：定位面板组

- 默认激活“快速定位”，另外两页是“固定快照”“时间标记”，沿用已有名称与功能。
- 快速定位显示完整事件集，按时间排序。同一帧的不同事件仍保留，避免合并后丢失信息。
- 一行优先显示时间和类型，说明可换行。列表使用整个面板剩余高度，不再固定为 220 的小窗口。
- 滚动条在需要时可见。虚拟化只减少实际创建的界面元素，不能减少列表数据。
- 手动浏览时不强制把列表滚回当前位置；列表滚动不触发游戏定位。
- 点击事件才发送定位请求，成功确认后更新当前项。失败时保留原来确认的位置并提示原因。

### 右侧：状态与压制缝面板组

- 默认激活“当前状态”，将双方 HP、灵力、动作和卡牌按 1P / 2P 清晰排列。
- “压制缝提示”直接作为面板标签，不再套一层同名可折叠标题。
- 现有阈值、缝提示及相关动作沿用现有含义，不因布局改动扩大计算范围。
- 卡牌原图沿用程序内资源，不拆解或复制用户的游戏目录。

### 底部：时间轴和唯一控制区

- 使用现有进度控制承载时间轴，默认高度约 96–120 DIP，始终可见。
- 播放/暂停、现有逐帧与逐秒步进、倍速、接管统一放在这里；页面其他面板不再复制。
- 先保留现有进度定位能力。事件轨道、时间轴缩放和区间编辑不作为本轮必做内容。
- 控制区不随定位列表滚动。窄窗口中允许在控制区内部排成两行，避免挤到时间轴只剩很短一截。
- 若应用其他页面仍需底栏控制，应复用同一个控制视图或同一组命令状态，播放页不能同时出现两套控制。

## 5. 面板调整规则

1. 面板之间使用约 5–6 DIP 的共享分隔线。拖动分隔线时，一侧增加多少，相邻区域就减少多少。
2. 面板到最小尺寸后停止继续压缩，不允许盖住游戏、时间轴或另一面板。
3. 第一阶段实现固定分区、标签切换和分隔线缩放。若继续支持标题拖动，应采用边缘停靠或中心合并标签，拖动时显示落点预览，取消拖动恢复原布局。
4. 默认不允许将面板自由堆叠在画面上，不生成工作区之外不可找回的面板。
5. 保存左右比例、标签位置和当前标签。窗口变小时先适配可用空间，恢复大窗口时可恢复宽屏布局。
6. “恢复默认布局”只恢复界面布局，不更改 REP、游戏位置、接管状态和分析结果。

## 6. 窗口与 DPI 适配

以**扣除应用导航和边距后的播放内容区域**为测量对象，单位是 WPF DIP，不能直接按显示器物理分辨率判断。以下是初始建议值，应通过实际布局验证微调。

| 可用内容宽度 | 布局 | 初始空间分配 |
| --- | --- | --- |
| ≥1120 DIP | 左定位组 + 中央画面 + 右状态组 | 左约 220、右约 260，其余给画面；两侧可调整 |
| 800–1119 DIP | 中央画面 + 右辅助组 | 将左右辅助标签合并到右侧，约 260；不删除任何标签 |
| <800 DIP | 上画面 + 下辅助标签组 + 固定时间控制 | 避免强撑三列；下方辅助组内部滚动，控制始终可见 |

可用高度较低时，缩减面板内边距、标题高度和辅助区高度，按比例缩小游戏画面；不让整页变成需要上下滚动才能找播放按钮的长页面。不能通过隐藏一部分事件或恢复重复快捷按钮来应对空间不足。

验证窗口尺寸至少覆盖 1920×1080、1440×900、1366×768；DPI 覆盖 100%、125%、150%。这些是验证输入，最终断点仍按实际 DIP 可用空间计算。

## 7. 布局必须服从播放状态

布局调整不能破坏刚修复的游戏同步。所有位置相关界面都订阅同一份“游戏已确认的位置”，目标位置单独保存。

| 状态 | 界面表现 |
| --- | --- |
| 已暂停 / 播放中 | 画面、时间、当前帧状态反映已确认的游戏帧；按钮状态一致 |
| 正在定位 | 显示目标时间及定位中状态；不能提前将目标显示为已到达 |
| 连续点击多个节点 | 保留最后一次目标；旧请求回执不能覆盖新目标 |
| 接管中 | 显示当前退出接管按键；其余按键交由游戏处理，复盘快捷键不拦截 |
| 退出接管、恢复中 | 明确显示正在恢复原 REP；完成后处于接管前位置并暂停 |
| 定位或恢复失败 | 显示失败原因，不用独立界面计时伪装成游戏已播放或已定位 |
| 离线轨迹 | 清楚标注离线；不能让轨迹进度控制另一个不匹配的游戏回放 |

拖分隔线、切辅助标签、恢复布局均不应发送播放/暂停/定位命令，也不应重新采集或重新计算整份 REP。

## 8. 实施落点与顺序

1. 替换 `ReplayWorkspace.cs` 的独立坐标画布，建立受容器约束的分区。首版可使用 WPF Grid、GridSplitter 与标签容器，无需为布局先引入大型依赖。
2. 将 `MainWindow.cs` 中 `ReplayPage` 的画面、状态、卡牌和步进控件拆为独立视图内容；保持同一个 `GameSurfaceHost` 实例与窗口租约，普通标签切换不得反复卸载和嵌入游戏。
3. 调整 `PopulateReplayTools`：保留全部快速定位数据与虚拟化，移除面板固定正文高度和外层重复滚动容器。
4. 整合 `BuildTransportBar` 与当前帧步进按钮，保证单个功能只有一个常驻入口。保留原回放/技能分支状态和返回入口。
5. 布局配置采用带版本的结构。旧 X / Y 坐标不能直接当作新停靠数据，应回退到新默认布局；旧书签、皮肤、快捷键和游戏路径不受影响。
6. 最后验证多尺寸、DPI、真实游戏嵌入、接管和分支返回，再更新可运行程序。

如需新依赖，优先在 `D:\ChatGPT\dependence` 查找或构建。本次方案本身不需要安装依赖、复制游戏或生成压缩包。

## 9. 验收标准

- 默认启动即可同时看到游戏、快速定位入口、当前状态入口和时间控制，无需先拖面板整理。
- 默认布局没有面板重叠；拖动分隔线不会露出大片未分配区域，不会把控件移出可见范围。
- 游戏画面保持 4:3，放大、缩小、切换辅助标签后仍能正常显示和操作。
- 全页面只保留一套常驻播放控制、一个倍速入口区域；没有输入录制功能。
- 快速定位条目数量等于完整事件数。对已有 238 个事件的样本，能浏览至最后一条，并用最后一个节点验证游戏与界面定位一致。
- 事件列表有大量条目时仍使用虚拟化；滚动列表、切换标签不执行新的回放分析。
- 面板调整前后，播放暂停、逐帧步进、连续定位、接管退出恢复和技能分支返回均通过实机验证。
- 皮肤令牌覆盖标签、分隔线、列表选中项、滚动条、时间控制和状态提示；默认、深色及自定义皮肤均可读。
- 缩小窗口、改变 DPI、重启程序后布局仍可用；恢复默认布局不会改变播放位置。
